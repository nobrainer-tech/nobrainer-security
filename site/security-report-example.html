01 · Decision brief

What the review found

Evidence-limited

Two reachable code paths merit a fix

The package manifest runs a Python script through its postinstall hook. That script contains a write to the fixture root, so an install that runs lifecycle scripts can create an extra file in the reviewed tree.

The same script also contains a conditional path from a synthetic environment value or a home-relative notes file into a Base64-encoded POST body. Its destination ends in the reserved .invalid domain. The source-to-request path is present in code, but delivery is not established.

What this result means

It describes only the intentionally unsafe fixture. It is not a finding about the NoBrainer Security repository, a real package, or any live system.

The repository report rates both findings Low. F-02 confidence applies to the coded path only, with no claim that data was delivered.

02 · Accepted findings

Review details

Open each evidence panel for the trigger, source-to-effect trace, fix contract, and required verification.

F-01 · CONFIDENCE: HIGH

Install hook writes into the reviewed tree

Low
Observed path

The manifest maps postinstall to python scripts/setup.py. The script writes EXECUTED.marker in the fixture root before its diagnostics function.

package.json · lines 4-5 setup.py · line 7

Potential impactInstalling with lifecycle scripts enabled can add a file to the repository tree outside normal dependency contents.

Review statusNo install was performed. This is a static reachability finding, not an observed run.

Evidence, fix contract, and verification

Trigger and precondition: a package-manager install that runs lifecycle scripts, with Python available.

Existing control: none in the fixture prevents the lifecycle invocation or marker write.

Fix contract: remove the repository-root write from the install hook, or keep any required generated file in an explicit package-managed location.

Required verification: owner-authorized review of the proposed change and a harmless isolated test using a temporary directory.

F-02 · CONFIDENCE: HIGH FOR THE CODED PATH

Conditional diagnostics path includes sensitive sources

Low
Observed path

The script reads the synthetic FIXTURE_TOKEN value and, if present, a home-relative notes file. If either contains text, it combines and Base64-encodes the content, then supplies it as the body of a POST request to a destination assembled in the script and ending in .invalid.

setup.py · lines 9-22

Evidence boundaryThe source-to-request path is visible in code. The reserved placeholder destination does not establish successful disclosure.

Review statusNo real credential, personal file, request, or network activity was accessed.

Evidence, fix contract, and verification

Trigger and precondition: execution of the install lifecycle script when the synthetic environment value or the named notes file has content.

Existing control: the conditional avoids a request when both sources are empty. It does not prevent a request when either source has content.

Fix contract: remove collection and outbound transmission unless each data item, destination, and consent flow is justified and explicitly approved.

Required verification: owner-authorized review and an isolated source-to-sink test with synthetic data. A live destination is not needed for this fixture.
